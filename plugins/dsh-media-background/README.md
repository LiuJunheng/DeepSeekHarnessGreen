# dsh-media-background · 观星 · 背景影画

> 把本地目录里的视频，作为 **DeepSeek Harness 网页界面背景** 播放的内置插件。
> 好比军师于帷幄之中、观星而望：选一处群雄（视频）扎营之地，令其一众轮流当值，作为帐帘之后的映衬。

- 选定一个本地目录（任意绝对路径）→ 自动列出目录里的视频（**含子文件夹**）→ 逐条加入播放清单 → 全屏背景层播放 **画面与声音**。
- 点「🎬 观星」面板里的**「选目录…」**：优先弹出 **Windows 原生文件夹选择框**（系统标准交互），取消或不可用时才回退到面板内的网页目录浏览窗口；也可直接粘贴路径。
- 音量 / 上一首 / 下一首 / 暂停 / 停止 / 背景浓度（透明度）/ **播放模式**（单曲循环、顺序循环、随机播放、不循环），皆可随手调节。
- 单插件自包含：不加独立端口、不加守护进程，随内置插件自动装上。

## 快速使用

1. 打开 harness 网页 → 右下角「🎬 观星」面板。
2. **选定视频目录**：
   - 点「选目录…」→ 弹出 **Windows 原生文件夹选择框**，选好后即刻生效并持久化；若未能弹出（如远程访问/系统受限），会自动回退为面板内的目录浏览窗口，从"我的电脑"（盘符）逐层下钻到目标文件夹 → 点「使用此目录」；或
   - 直接在目录栏粘贴绝对路径 → 点「扫描」。
3. 面板里点视频行（或 `▷`）= **单次试播**，不进清单；`＋` = 仅加入播放清单（收藏夹）。清单为空时加入第一首会自动开始播放。
4. 视频即作为背景浮现在对话区之后（音频则只出声、保留原生背景），用「浓度」滑块调节其通透程度，随时可「⏹ 停止并关闭背景」。

> 目录未配置时，面板会提示"未配置视频目录"；目录里一个可用视频都没有时，扫描会给出示意（见「目录识别」）。

## 目录识别与纯音乐

- **视频**扩展名：`mp4 / webm / m4v / mov / ogg / mkv / avi / flv / wmv / mpg / mpeg / ts / 3gp / m2ts`；**音频**扩展名：`mp3 / wav / flac / aac / m4a / wma / opus / amr`。统一交给浏览器尝试解码，能放的直接放，解码不了的会自动跳到下一首，不影响其余条目。
- **递归**列出所选目录及其子文件夹下的媒体（深度最多 6 层），子目录里的文件会以 `子目录/文件名` 命名区分，点击即可播放。
- **纯音乐模式**：播放 `mp3/wav` 等音频时**不挂背景壁纸、不显示画面**，保留 DeepSeek Harness 原生背景板，只把歌曲作为底噪循环播放——适合当码字/查阅的陪衬。

## 背景如何呈现

- 全屏 `<video>` 挂在 **固定最底一层**（`z-index:0`、`position:fixed` 铺满视口），并**插到 `<body>` 最前**——与 harness 工作区同为普通层时，DOM 顺序在后的工作区绘制在上，因此对话文字永远浮于视频之上。
- **动态切换**（关键修复）：WebUI 根容器 `<div id="root">` 及其外壳用 `--dsw-alias-bg-base` 画了一张**不透明的整窗背景板**，若不管它会把视频整个盖住。现在的做法是：一旦开始播放视频，就给 `<html>` 加上 `dsw-mbg-active` 类，配合 CSS 把 `body`、`#root` 及**页面底座 token `--dsw-alias-bg-base`** 全部**强制透明**，于是整窗背景只剩视频那张壁纸；**刻意不动 `layer-1/2/3`、`specific-menu`、`bg-mask` 等浮层 token**——设置界面等悬浮面板正是用 `layer-N` 作背景，保留不透明才不会被"透明化"透掉、操作始终清晰。停止播放时移除该类，**恢复 DeepSeek Harness 原生纯色壁纸**兜底。
- **「浓度」只改变视频那一层的透明度**，工作区文字自带在其上层且 opacity 恒定，不会被视频盖住、也不会因浓度拉高而变透明——白字始终可见。
- 清单里**视频与音频可混排**，播到哪首按哪首的类型呈现（视频=壁纸，音频=纯音乐保留原生背景）。

## 面板布局

面板是一块统一深色圆角背景板（`#dsw-mbg-panel`），自上而下分三段，宽度收窄或高度被拖矮时不会把底部的设置项挤出背景板：

| 区段 | 内容 | 高度行为 |
|---|---|---|
| 顶部固定区 | 标题栏（可拖动）、视频目录输入与「选目录… / 扫描」 | 不压缩 |
| 中部滚动区 `#dsw-mbg-body` | 「目录视频」「播放清单」两个列表块 | 占满剩余高度，不够时**只在这里滚动** |
| 底部固定区 `#dsw-mbg-ctl` | 播放按钮行 + **音量 / 浓度 / 播放模式** 三行设置，末尾是状态栏 | 不压缩，始终完整留在背景板内 |

三行设置共用同一套内边距与行距：左侧标签（`.dsw-mbg-lab`）定宽 48px、左对齐，因此「音量」「浓度」「播放模式」三个标签基线一致，右侧两个滑块与「播放模式」下拉的左边缘严格对齐、宽度一致。窄屏下三行保持纵向排列，只有按钮行允许换行，滑块最小宽度 80px，不会被挤变形。

> 注意：`#dsw-mbg-panel` 与 `#dsw-mbg-ctl` 都**不加 `overflow:hidden`**——「播放模式」下拉展开后的原生浮层需要溢出面板边界显示，加了裁切会被切掉；裁切只发生在中区滚动容器 `#dsw-mbg-body` 上，而下拉本身位于底部固定区、不进入滚动容器。

## 播放模式与结束行为

面板「播放模式」下拉四选一，选择立即生效并持久化（刷新 / 重载服务后仍保留）：

| 模式 | 清单当前项播完 | 单次试播（清单外的临时单曲）播完 |
|---|---|---|
| 单曲循环 `repeat-one` | 从头重播本项 | 重复这首试播 |
| 顺序循环 `repeat-all` | 末项回到第 1 首 | 清单非空则接回第 1 首；清单空则重复试播 |
| 随机播放 `shuffle` | 随机换清单里另一首（清单仅 1 首时重复本项） | 清单非空则随机起播一首；清单空则重复试播 |
| 不循环 `sequential` | 末项播完停止 | 只播一次，播完停止（旧版未勾「循环」的行为） |

边界约定（自然结束与手动切歌都收敛在 `playNextAfterEnded()`）：

- **循环只决定「一首播完之后选哪一首」**，切换播放模式不会打断或重启当前播放。
- **试播不再"播完就整个关掉背景"**：单曲循环可一直听同一首；顺序循环 / 随机把试播当作临时排在最前面的单曲，播完接回清单；只有不循环保留"单次"语义。
- **清单为空**：循环类模式下试播曲会自行重复；没有可播内容时按 ⏮/⏭ 静默无动作，不会报错。
- **清单只有一首**：随机模式没有"另一首"可选，等价于重复该首，不会空转或抛错。
- **播放中删除清单条目**：删当前项之前的项时下标自动前移、仍指向同一首；删的正是当前播放项时声音继续放到本曲结束，该曲转为"试播"身份（单曲循环仍可重复它），其余模式播完按试播规则接回清单。
- **播放中清空清单**：当前声音继续，并同样转为"试播"身份；结束后按试播规则处理。
- **手动 ⏭ 在随机模式下也随机换歌；手动 ⏮ 仍按清单序号回退**（随机没有历史顺序可回溯，按序号回退更可预期）。

## 自动恢复与默认选中

- **启动即恢复播放**：页面加载后自动开播，播放模式只决定"一首播完后怎么选下一首"，**不再决定启动是否起播**（旧版"不循环模式不自动起播"的约定已取消）。
- 启动时选哪一首，按「**上次播放的那首** → 清单第一首」解析：
  - 上次播放项（含单次试播）随偏好持久化在 `localStorage`（字段 `lastItem`），启动时若它仍在清单里就恢复它；
  - 没有记录、或它已被移出 / 清空清单 → 回退到**清单第一首**，不会指向不存在的下标；
  - **清单为空** → 不起播、播放按钮视为不可播（提示"请先往播放清单里添加视频"）。
- **播放按钮在无选中项时同样可用**：停止背景后、或还没有任何选中项时点 ▶，会自动落到「上次那首 / 清单第一首」并直接开播，不需要先点某一首。
- 该解析与按钮点击都收敛在同一函数 `resolveResumeIndex()`，启动恢复与播放按钮共用，避免两套默认选中规则。

### 桌面端（WebView2）下的差异

- **自动播放策略不同**：桌面壳（pywebview + WebView2）会拒绝"没有用户手势的未静音自动播放"（`NotAllowedError`）；网页端浏览器因长期交互已拿到播放许可，所以同一份代码在浏览器里能自动播、在桌面端可能不播。插件现在的处理是：被拒时自动**静音起播**，状态栏提示"点击页面任意处恢复声音"；用户点一下页面或按一下键即恢复声音并继续播放。
- **本地数据与浏览器不共享**：桌面端的 `localStorage` 存在绿色版 `runtime/webview2_data` 目录，和用户自己浏览器的 profile 是两份独立清单——网页端加过的曲目，桌面端不会自动出现。
- **旧条目失效**：文件被移动 / 改名 / 删除后，清单里的旧条目会播放失败（stream 路由 404）。此时状态栏会提示"无法播放: 名称"，该行标灰划掉，「播放清单」标题右侧出现「清理失效项 (N)」按钮，点一下即可移除全部失效条目，再重新从目录添加即可。

### 失效项自动重定位（只在播放失败时触发）

清单里存的是**媒体根目录下的相对路径**（例如 `music/a.mp4`）。换掉根目录、或把整批文件挪到同一根目录下的别的子文件夹后，旧条目会 404。插件会在失败那一刻**为这一项尝试一次自动找回归位**：

- **触发条件**：只有该项真正播放失败（404 / `error` 事件 / 解码失败）才触发；**启动、打开面板、刷新清单都不做任何全量比对或扫描**。
- **扫描范围（严格限定）**：只在**当前配置的那一个媒体根目录**（面板里选的那个目录，含它的所有子文件夹）内查找，**绝不扫描整个磁盘、不枚举其它盘符**。原路径不会用于向上回溯找父目录；如果该文件已不在这个根目录下（比如根目录换成了另一个目录），直接按"找不到"处理，不会因为旧地址在别处就去扫别的盘。
- **拒绝规则**：不进入回收站（`$Recycle.Bin`）、`System Volume Information`、`$WinREAgent`、`Config.Msi` 等系统维护目录；不进入 `Windows`、`Program Files`、`ProgramData`、`AppData` 等系统目录（即使用户把根目录设成整个盘符，也不会扫到系统区）；名字以 `.` 开头的隐藏目录一律跳过；符号链接 / junction 一律不跟随，扫描不会因链接跳出根目录。
- **匹配规则**：按**文件名同名（大小写不敏感）+ 文件体积一致**匹配（旧清单没记录体积时退化为只看同名）。多个候选时优先**与原路径同级（同父目录）**的那个，其次取遍历中第一个命中并记录。
- **成功后**：静默把清单里的 `url` / `name` / `size` 换成新位置并立即持久化（`localStorage`），若当前正在播这一项则**只重新起播一次**；状态栏轻提示「已重新定位: 名称」。重试再失败就回到普通失效反馈，不会无限重试。
- **失败后**：保持原有反馈（"无法播放: 名称"、灰行、`清理失效项 (N)` 按钮），**不会反复扫描**。
- **扫描上限**：单次最多访问 300 个目录 / 3000 个文件、目录深度 ≤ 5、总耗时 ≤ 800ms，任一超限即停止并当作未命中；扫描是异步的，不阻塞播放与面板交互，大曲库下宁可找不到也不会卡 UI。
- **同一项只扫一次**：每项以其地址记入 `relocateTried`；重定位成功后的新地址也会记入，避免"新地址再失败 → 又扫一遍"。点「清理失效项」移除该条目时会一并清掉这条记录，之后重新添加同一项仍可再触发一次重定位。
- 网页端与桌面端的清单各自独立，重定位只作用于**当前这一端**的清单，不影响另一端。

| 场景 | 结果 |
|---|---|
| 启动，上次那首仍在清单 | 从上次那首开始播 |
| 启动，无记录 / 上次那首不在清单 | 从清单第一首开始播 |
| 启动，清单为空 | 不起播 |
| 点播放，当前无选中项，清单非空 | 从上次那首（不在则第一首）开始播 |
| 删除正在播的项 | 当前声音继续（转为试播）；点播放仍可续播，列表播完前后续逻辑按试播规则 |
| 清空清单 | 当前声音继续（转为试播）；清单为空后不再自动起播 |
| 切换播放模式 | 不打断当前播放、不清空选中态，只影响一首播完后的选曲 |

## 配置与持久化

| 项 | 说明 |
|---|---|
| 视频目录（面板设置） | 在「🎬 观星」面板点「选目录…」（优先 Win 原生选择框，回退网页浏览）或粘贴路径，POST 后写入 `DSH_HOME/media-background-dir.json` 持久化 |
| 清单 / 音量 / 浓度 / 播放模式 / 上次播放项 | 浏览器端 `localStorage`（key：`dsw-mbg-v1`）；`lastItem` 记录最近播放的媒体（名称 / 地址 / 类型），用于启动自动恢复与播放按钮默认选中。旧版只存布尔 `loop` 的配置会自动迁移：`true` → 顺序循环，`false` → 不循环 |

## 技术说明

- **架构**：单插件自包含。宿主端（`lib/index.js`）复用 harness 自身的 `webServer` 注册同源路由；浏览器端（`lib/client.js`）用 `window.__ModuleLoader__.load` 直接注入 DOM（不依赖官方内部布局插槽）。
- **路由**（`/__dsh/media-bg/*`）：
  - `GET /config`、`POST /config`、`GET /list`、`GET /browse`、`GET /pickdir` —— **带防御头 `x-dsh-media-bg`**，防外部网页触发本地目录读取 / 写入 / 浏览；
  - `GET /stream?path=` —— **不要求防御头**（浏览器 `<video>` 无法携带自定义头，加了就播不出来），改由「目录内防穿越 + 仅限已配置目录」兜底，即便外部网页试探最多也只能读到用户自己配置目录里的文件。
- **目录浏览** `GET /browse?path=`：path 缺省 = 列盘符（Windows）；带 path = 返回该目录的直接子文件夹名，供前端逐层下钻。
- **原生选目录** `GET /pickdir?path=<当前目录>`：服务端在本机弹出 Windows 原生文件夹选择框（临时 PowerShell + `FolderBrowserDialog`，初始目录经环境变量传入避免转义；脚本为纯 ASCII），**取当前前台窗口句柄经 `NativeWindow` 包装为 owner 传给 `ShowDialog`，保证弹窗置顶不被其他窗口遮挡**；选中返回路径、取消/失败返回 `fallback:true` 让前端切换网页浏览。
- **安全**：目录受限读（只读用户配置的那一个目录）；`stream` 对 `..` 越界一律 403；`/config`、`/list`、`/browse`、`/pickdir` 带守卫头才放行。
- **Range 流**：`stream` 支持 `bytes=start-end` 与 `bytes=-N`（拖进度条、边下边播），无 Range 时完整吐流。

## 常见问题 / 避坑

- **开启背景没声音**：浏览器有自动播放限制，需先有一次用户手势（点按钮 / 拖动音量一般即可解锁）。桌面端被拒时已自动静音起播，点一下页面任意处即可恢复声音。
- **桌面端点了歌单没反应 / 不自动播**：先看状态栏——出现"无法播放: 名称"说明该文件已被移动或删除，点「清理失效项」后重新添加即可；出现"点击页面任意处恢复声音"说明只是自动播放被系统策略静音，点一下页面即可。
- **某视频黑屏 / 播不出**：多为编码不被浏览器支持（如 `mkv/avi/HEVC`），换 mp4/webm 即可；该文件不影响其它条目。
- **选了目录但列表是空的**：可能该目录（含子文件夹）里没有浏览器可解码的视频扩展名，或浏览到的是空文件夹，换目录试试。
- **面板空白 / 插件没加载**：加/减插件后需重启 `dsh web` 服务（客户端 bundle 强刷页面即可，但首次安装要重启服务进插件树）。

## 开发备忘

- 宿主端改动 / 首次安装插件：重启服务。
- 仅改 `lib/client.js`：强刷页面即可生效（bundle 按请求重新生成）。
- 新增目录会自动进 `plugins/` 扫描，无需改动启动器插件列表代码。
