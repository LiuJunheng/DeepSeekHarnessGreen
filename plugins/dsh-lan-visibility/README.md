# dsh-lan-visibility · 局域网可见性权限

在局域网模式(`dsh_host=0.0.0.0`)下,给**每个工作区 / 对话**单独设置可见范围:

- **仅本机可见(默认)**:只有本机回环地址(127.0.0.1 / ::1,桌面壳 / 本机浏览器)能看到并操作;
- **局域网可见**:同一局域网的其它设备(非回环来源)也能看到并操作该工作区/对话(可看可管理)。

> 本插件由「绿色版整合」项目内置,不修改任何官方文件。默认可见性 = 仅本机可见(隐私优先)。

### 背景(为什么可以做)

DSH Web 是单用户、无账号体系的 WebUI:本机浏览器与局域网设备**都会被当作同一个 `owner`(所有者)**,因此默认情况下局域网用户能看到全部会话/工作区。但官方 `@deepseek-ai/dsh-api-remote-access` 内置了面向「非 owner 访问者」的方法级访问控制骨架(网关对非 owner 的每次调用/事件判权,会话列表/搜索/事件流/工作区流自带过滤),当前没有注册任何策略所以处于"休眠"。本插件在连接层把**非回环来源**的连接标记为 `lan` 身份,并注册 `lan` 策略只放行「被共享」的资源——官方已有的过滤逻辑随之自动生效,不需要改官方代码。

## 使用

1. 启动服务后打开 WebUI →「设置」→「局域网可见性」:
   - 上半部分「工作区」:每个工作区一个「局域网可见」开关;
   - 下半部分「对话」:每个会话一个「局域网可见」开关(会话默认跟随所属工作区的设置,显式勾选后以会话自身为准);
   - 对话行标题与左侧会话栏一致(读取会话的 title 投影; 尚未生成标题的新会话回退显示短 id);
2. **会话右键菜单**:在左侧会话列表任意会话上点「...」,菜单里新增「共享给局域网 / 取消共享给局域网」一项(官方 `sidebar.workspaces.session.menu.item` 插槽,排在「归档会话」与「复制 Session ID」之间)。点击即切换该会话的显式可见性并关闭菜单。
   - 工作区右键菜单**没有官方插槽**(官方工作区「...」菜单是写死的「重命名 / 删除」),因此工作区的共享开关仍在设置页卡片里操作。
   - 设置页卡片与会话右键菜单项只在**本机(127.0.0.1 / localhost)打开**的页面注册;局域网设备打开的页面不显示这两个管理入口(避免 403 空转)。
3. **会话列表行标签**:官方侧栏每个会话行的标题后面会显示一个小标签——「局域网」(强调色) 或「本机」(弱化色),一眼区分哪些会话对局域网可见。标签由客户端 DOM 注入实现(官方没有「标题后」插槽):行元素 `[data-row-key="session:<id>"]` 的 `[状态点][标题][时间][操作]` 结构中,把标签插在标题与时间之间;React 重建行时由 MutationObserver 补回,可见性快照随右键菜单/设置页切换即时刷新,并每 30 秒周期刷新一次。
4. **局域网地址(复制一键打开链接)**:设置页顶部自动检测本机网卡 IPv4 地址,生成 `http://<局域网IP>:<端口>/?token=<访问凭据>` 链接(带「复制链接」按钮),直接发给手机/另一台电脑打开即可——链接自带 30 天访问凭据,不需要对方手动输入 token。
   - 仅当服务处于局域网模式(`dsh_host=0.0.0.0`)时显示链接;若服务只绑定本机(127.0.0.1),卡片会提示「请在启动器里打开局域网模式并重启服务」。
   - 链接由宿主端路由 `GET /__dsh/lan-visibility/network` 生成(读取 webServer 的绑定地址/端口 + 网卡 IP + connection 的 launch token)。
5. 勾选 = 共享给局域网;取消勾选 = 仅本机。设置即时生效(无需重启)。
6. 未做任何勾选时,局域网设备打开界面看不到任何工作区/对话——这是默认行为。

### 可见性优先级(覆盖规则)

会话的**显式设置优先**,其次才看所属工作区的设置,最后是默认值:

```
会话显式设置("局域网"/"仅本机")  >  所属工作区设置  >  默认(仅本机)
```

- 工作区 = 局域网可见,但某个会话显式设为「仅本机」→ 该会话**仍然只有本机可见**(会话显式优先);
- 工作区 = 仅本机,但某个会话显式设为「局域网可见」→ 该会话对局域网可见(显式优先);
- 会话没有任何显式设置时,才跟随工作区。

## 机制(维护必读)

- **连接层分流**:运行时包装 `connection.admit` / `connection.admitConnection`,
  非回环来源的连接一律以 `principal.kind='lan'` 的 Peer 接入;回环来源保持官方 owner 行为。
  每个 WebSocket 连接独占一个 lan Peer,连接关闭即释放。
- **访问策略**:通过 `@deepseek-ai/dsh-api-remote-access` 注册 `lan` 策略:
  - `global` 资源只放行 `session/list`、`session/search`、`session/modelCatalog`、`workspace/follow`;
  - 已共享的工作区放行 `workspace` 命名空间全部动作;
  - 已共享(或所属工作区已共享)的会话放行 `session` + `workspace` 命名空间全部动作。
  - 官方会话列表 / 搜索 / 会话事件流 / 工作区流本就调用 `remoteAccess.allows()` 过滤,自动生效;
    按 ID 打开会话会经网关 `decide()` 拦截;`/api/file` 等精确 Fetch 路由对非 owner 已 403。
- **侧车存储**:`$DSH_HOME/storages/lan_visibility.json`(原子写),结构:
  ```json
  { "version": 1, "sessions": { "<sessionId>": "lan" | "local" }, "workspaces": { "<workspaceId>": "lan" | "local" } }
  ```
  未记录 = 默认仅本机可见;会话未记录时跟随所属工作区。
- **管理路由**(仅本机回环 + 自定义头 `x-dsh-lan-visibility: 1` 可调用):
  - `GET /__dsh/lan-visibility/list` — 工作区/会话清单 + 可见性;
  - `POST /__dsh/lan-visibility/set` — 切换可见性, body `{ kind: "session"|"workspace", id: string, visible: boolean }`;
  - `GET /__dsh/lan-visibility/network` — 绑定地址/端口/网卡 IPv4/一键打开链接(见「使用」第 4 条)。

## 自测验收(建议)

1. 本机(127.0.0.1)访问:全部功能与插件安装前一致;
2. 局域网设备访问:只能看到「局域网可见」的会话/工作区;隐藏会话在列表不可见、按 ID 打开被拒、文件路由 `/api/file` 返回 403;
3. 设置页/右键菜单切换后**即时生效**(无需重启服务),会话行标签同步变化;
4. 重启服务/断网重连后可见性设置保持(侧车文件持久化);
5. 局域网用户无法调用管理路由(403),也看不到设置页卡片与右键菜单项;
6. dsh 升级重装后插件随插件树自动加载,无需重新补丁(本插件不修改官方文件)。

## 已知边界

- 「本机」= TCP 来源为回环地址。**从本机浏览器用局域网 IP(如 192.168.x.x)打开会被判为局域网来源**——
  本机请用 `127.0.0.1` / `localhost` 打开(绿色版默认就是)。
- 局域网设备仍需先通过带 token 的访问地址换 Cookie(或 `config.json` 里 `dsh_require_auth=false` 关认证),
  这是既有行为,与可见性无关。
- 局域网用户打开设置页「局域网可见性」卡片会 403(管理路由仅本机可用)。
- 局域网用户不参与实时"会话列表"事件(事件资源按 `event:*` 放行白名单控制,默认全拒),列表在刷新后更新;
  已共享会话内的聊天流(`session/follow`)正常实时。
- 自有插件路由(文件浏览器等)不在本插件的访问控制范围内(用户决策:暂不处理)。

## 调试

设置环境变量 `DSH_LAN_VISIBILITY_SIMULATE_LAN=1` 后,请求带 `x-dsh-simulate-lan: 1` 头即被当作
局域网来源,便于本机 curl 验证权限(仅测试用,默认关闭)。
