New Features

  • Skill Center plugin (dsh-skill-center): fills the gap left by the official WebUI — a proper skill management entry, as a pure plugin with zero dependencies and no build step.
  • Left-sidebar "Skills" entry: opens the central Skill Center page, grouped into Official skills (read-only) / My skills (manageable) / Other sources (read-only) / Disabled, with search and SKILL.md preview.
  • Composer "Skills" picker: searchable list of user-invocable skills; clicking inserts /name into the draft and sends through the native explicit-invocation path (Instructions card appears) — no need to type the slash manually.
  • Personal skill management: create, edit and save (atomic write), disable / enable, remove (to trash), open the folder in the file manager. Personal skills live in runtime/dsh-home/skills, physically separated from official skills — nothing is copied and no official file is modified.
  • ZIP import: import one or more skills at once (<name>/SKILL.md, root-level SKILL.md, single wrapper directory, skills/<name>/SKILL.md, root-level <name>.md), compatible with TRAE / WorkBuddy exports (explicit directory entries, ./ prefixes); you can also drop a ZIP onto the page.
  • Safety: rejects zip-slip (absolute paths / ..), ZIP bombs (compression ratio > 200), encrypted ZIPs, ZIP64, multi-volume and symlink entries; single SKILL.md ≤ 256KB, single bundle ≤ 8MB / ≤ 200 files; routes are loopback-only.
  • Name conflicts: fail by default; with "Overwrite" the old skill goes to trash, and shadowing an official skill requires explicitly checking "Allow shadowing".

Technical Architecture

  • Dual-end plugin package (dsh.bundle.patch + dsh.client), consistent with the other bundled plugins:
  • Host side lib/index.js registers 9 /__dsh/skill-center/* routes, reading official skills via ctx.skills and managing personal skills with Node fs;
  • Client side lib/client.js registers 3 slots: sidebar.panellist (left entry), main (central page), conversation.input.left (composer button and picker);
  • The client imports no @deepseek-ai/dsh-client-* packages and styles itself with --dsw-alias-* theme tokens; if a slot is missing it only logs console.warn and skips, without affecting other plugins.

Internal Changes (no user-visible behavior change)

  • Bundled plugins dsh-memory / dsh-session-rewind have their @deepseek-ai/* dependencies synced to the host version 0.2.1-rc.3 (launcher self-healing rewrite).
  • The trilingual site home page now includes a Skill Center plugin card, and the plugin-count copy is updated to 12.

Version Bump

  • GREEN_VERSION: 1.0.45 → 1.0.46

Upgrade Notes

  • Green edition: overwrite install is sufficient. Skill Center ships bundled and appears in the left sidebar after the environment is installed.
  • Personal skills are kept in runtime/dsh-home/skills and survive upgrades; removed skills can be recovered manually from runtime/dsh-home/skill-center/trash/.

New Features

  • Support for DSH v0.1.7's new language settings mechanism: DSH v0.1.7 deprecated the locale.preference field in settings.yaml in favor of the Cordis patch mechanism. The launcher's _apply_language_preference() now writes a locale patch entry (id=locale, config.preference) into profile/cordis.patch.yml, using safe PyYAML parsing, preserving the file's leading comments, and coexisting with official native patches
  • Impact: with the older launcher running DSH v0.1.7, the language preference would not take effect — resolved in this release
  • PyYAML-missing fallback: The bundled Python already ships PyYAML; if a packaged EXE fails to collect it, the launcher now only logs a warning instead of crashing the main flow

Internal Changes (no user-visible behavior change)

  • Removed 76 lines of zero-reference dead code: _npm_view / _write_i18n_bridge_to_plugins / switch_src / _tray_log and its 11 call sites, etc.
  • Removed 3 obsolete i18n entries (green_update.detected_title / detected_msg / failed_title) and the unused config key dsh_heap_limit_mb
  • No longer writes tray_menu.log into the program root: this tray diagnostic log was a temporary artifact from tray debugging and has been removed entirely (previously every tray action appended to it)
  • Bundled plugins dsh-memory / dsh-session-rewind have their @deepseek-ai/* dependencies synced to the host version (0.1.7-rc.1)
  • Both EXEs rebuilt

Version Bump

  • GREEN_VERSION: 1.0.41 → 1.0.42

Upgrade Notes

  • Green edition: overwrite install is sufficient
  • If you manually configured a language preference in settings.yaml, the launcher migrates it to cordis.patch.yml automatically after upgrading DSH to v0.1.7 — no manual action needed
